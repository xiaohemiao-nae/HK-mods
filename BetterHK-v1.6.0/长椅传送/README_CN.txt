========================================================================
 Better HK · 长椅传送  ——  《空洞骑士》长椅互传（地图点击版，v1.6.0）
 作者：小禾苗
========================================================================

【这是什么】
坐在长椅上打开地图，地图上会出现其他已解锁长椅的图标；
用鼠标点那个图标，就直接传送到那张长椅。
传送后角色会直接坐在目标长椅上，和正常休息完全一样（存档点也随之更新）。

  用法：坐下休息 → 打开地图 → 点地图上的长椅图标 → 传送完成

关于鼠标指针：游戏在地图界面本来就把系统光标藏起来了（Cursor.visible = false，
而且把 lockState 设成 Locked），地图一向靠手柄/键盘导航，所以根本找不到指针。
本 mod 只在你「坐在长椅上打开地图」期间把光标放出来：
  · 优先直接显示系统光标（最跟手、零延迟）；
  · 万一游戏每帧又把光标藏回去，就在屏幕上自己画一个箭头 ——
    位置取的是真实鼠标坐标，和点击判定用的是同一套，看到哪儿就点中哪儿。
关掉地图后立刻交还给游戏自己管，不会留下「光标关不掉的」后遗症。
诊断信息里会显示 cursor=system（系统光标）或 cursor=self（自绘），
按 F1 就能看到当前用的是哪种。

规则：
  · 必须先坐在长椅上（休息状态），地图上才会出现图标；
  · 没坐在长椅上时，地图保持原版行为，点击不触发任何传送；
  · 当前坐着的那张长椅显示为灰色，不可点击；
  · 图标只出现在地图上已经可见（探索过 / 买过地图）的区域内；
  · 少数场景本来就没有地图块（例如神居 GG_* 系列、白宫内部），
    这些长椅不会出现在地图上，属于游戏本身没画，不是 mod 漏了。
  · F1 = 开关左上角的诊断信息，平时不需要用。

图标位置怎么来的：游戏的地图层级本来就是「区域 → 场景块」，
每个场景块的名字就是场景名（游戏自己也靠这个名字判断哪块地图要显示）。
所以本 mod 只是按名字找到对应场景块、把图标画在它的位置上，
不维护任何自定义地图坐标表，也不会因为地图缩放/拖动而错位。

长椅清单来自存档里的「已遇见长椅」记录（PlayerData.scenesEncounteredBench）；
读不到时退回内置全表（51 个长椅场景）。每张长椅的复活点名（marker）
已从游戏资源预先提取、随 DLL 内置，不需要「先坐一次」。
进入某个场景时还会自动校正该场景的 marker，越玩越准。

【和 3 倍移速补丁的关系】
两者完全独立：
  · 3 倍移速是「改游戏程序集里 24 个字节」，由同级目录「移速3倍」负责；
  · BenchWarp 是「一个独立的小 DLL + 两份 Unity 清单登记」，由本目录负责。
可以只装其中一个，也可以两个都装，互不冲突。

【安装：包里已经带了编译好的 DLL，不用装 SDK】
长椅互传属于「新增逻辑」，做不到只改几个字节；它需要真正加载一段代码。
好消息是不用装任何 mod 加载器（Lumafly / Modding API 都不需要），
Unity 6 自带的装配清单就能挂载自编译的 DLL。

  1) 完全退出游戏，双击 Install.bat
     它会直接把包里 bin\BenchWarp.dll 放进游戏目录，并在两份清单里登记。
     看到 "校验通过：清单已正确登记" 即成功。

之后照常从 Steam 启动游戏；进存档坐上长椅、打开地图就能看到图标。

【只有想改代码时，才需要装 .NET SDK】
  · 双击 InstallSDK8.bat（会自动请求管理员权限）
      它会从微软官方接口取当时最新的 8.0 SDK 版本号与地址，
      下载后核对 SHA-512 与官方公布值一致，再静默安装。
      已经装过 SDK 8 时会直接提示并退出，不会重复安装。
  · 然后双击 Build.bat 重新编译出 bin\BenchWarp.dll
  · 再双击 Install.bat 覆盖安装。

  注意：不要用 winget。实测 `winget install Microsoft.DotNet.SDK.8`
  走的是 WinHTTP，默认不经过系统代理，在需要代理的网络里直接报
  0x80072efd（无法与服务器建立连接），看起来像"下载失败"其实是没走代理。
  InstallSDK8.bat 会自动依次尝试：指定代理 → HTTP(S)_PROXY 环境变量 →
  系统代理设置 → 直连。若你的代理没被自动识别，可以指定端口：
      InstallSDK8.bat -Proxy http://127.0.0.1:7890
  （端口填你自己代理软件的）

  已被实测验证：SDK 8.0.428 + 本机 .NET 8 运行时共存编译通过，0 警告 0 错误；
  只装运行时（没有 SDK）不足以编译。

【怎么确认生效】
1. 双击 Status.bat，应显示：
     DLL      : 已安装 (...)
     清单登记 : 已登记（BenchWarp.dll）
     启动入口 : 已登记（BenchWarpMod.Bootstrap.Init）
2. 启动游戏进存档 → 走到一张长椅坐下 → 打开地图。
   应看到其他长椅位置出现青色图标（带场景名），鼠标点击即可传送。
   如果没反应，看日志：
     %USERPROFILE%\AppData\LocalLow\Team Cherry\Hollow Knight\BenchWarp.log
   · 有 "BenchWarp v1.6.0 loaded (map-click edition)" → DLL 已被加载；
   · 有 "map opened | area=N/20 compass=1" → 地图打开被识别到了
     （关图时只有当前所在区域激活，约 area=1/20；开图时几乎所有区域一起激活）；
   · 有 "session start: resting, atBench=True" → 确认是在长椅上开的图，
     只有这一行出现，图标才会显示；
   · 有 "map blocks cached: N area(s), M scene block(s)" → 地图块识别成功，
     M 是缓存到的场景块数量；
   · 有 "map click -> <场景名>" → 点击命中，正在传送；
   · 每 30 秒一行的 "beat ..." 是心跳，证明 mod 还在运行；
   · 完全没有这个文件 → DLL 没被加载，请检查 Status.bat 输出并重装。

【怎么卸载】
完全退出游戏，双击 Uninstall.bat：
  · 删除 hollow_knight_Data\Managed\BenchWarp.dll
  · 从 ScriptingAssemblies.json / RuntimeInitializeOnLoads.json 里精确移除本 mod 的条目
    （改完会重新校验，names 与 types 数量保持一致，不会破坏游戏启动）
长椅记录文件 BenchWarp_benches.txt 会保留在存档目录，可自行删除。

【安全性 / 改动范围】
  · 不改游戏任何 .dll 里的一个字节（3 倍移速补丁除外，那是另一个功能）；
  · 只新增 1 个 DLL + 在两份 Unity 清单末尾各追加 1 条记录；
    首次安装会把原始清单备份到 backups\*.orig；
  · 卸载按「条目」移除，不依赖备份也能干净还原；
  · 不进游戏时不产生任何后台进程，没有常驻服务。
风险提示：
  · 传送会把存档点改成目标长椅（这是「坐在长椅上」的正常结果）。
  · 传送过程中不要强行退出游戏，等场景加载完成。
  · 游戏更新后，Unity 的清单文件可能被重写：重跑一次 Install.bat 即可。

【实现原理（一句话版）】
复用游戏自带的复活流程：把「复活点」指向目标长椅，再调用
GameManager.ReadyForRespawn(false) 让游戏自己加载该场景；进场时游戏检测到
RespawningHero 会调用 HeroController.Respawn()，后者按 respawnMarkerName
定位长椅复活点并把角色放上去、驱动该长椅的 "Bench Control" FSM 进入
"RespawnResting" 状态 —— 于是你和正常休息一模一样地坐在了目标长椅上。
同场景传送则直接走 HeroController.Respawn()。
